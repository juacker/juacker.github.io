  • OpenTelemetry Collector v0.166.0 adds gRPC address-list shuffling, listener middleware extensions and FIPS 140-3 startup logging open-telemetry/opentelemetry-collector - released 23 Nov 2026 22:26 UTC

    The release adds the pick_first.shuffle_address_list option for gRPC clients that use the pick_first balancer, so clients resolving the same address list no longer all connect to the first address; the option is off by default and implements gRFC A62. Listener middleware extensions can now create HTTP and gRPC server listeners, and the Collector reports in its startup log line whether it is running in FIPS 140-3 mode.

  • OpenTelemetry Specification v1.63.0 marks environment variables as stable context propagation carriers and adds a traces data model open-telemetry/opentelemetry-specification - released 23 Nov 2026 17:25 UTC

    Release 1.63.0 stabilizes environment variables as context propagation carriers and adds the traces data model to the specification. It introduces a development span type with an optional span creation parameter, ReadableSpan access and SDK syntax validation, and allows an exception to the finite upper bound on exporter Export calls for synchronous output through APIs without deadline or cancellation support.

  • SigNoz v0.152.0 removes the saved-view v1 APIs and starts moving log bodies to native JSON storage SigNoz/signoz - released 26 Nov 2026 09:28 UTC

    The release deletes the saved view v1 APIs, deprecated since v0.137.0, so callers using them directly have to migrate to v2. Log bodies move to native JSON storage with dual ingestion, which the project says requires additional collector CPU and memory, ClickHouse CPU and log disk capacity before the upgrade.

  • OpenObserve v1.2.0 rebuilds dashboards, ships a second-generation metrics explorer and adds product analytics and continuous profiling openobserve/openobserve - released 24 Nov 2026 12:39 UTC

    More than 900 changes from 40 contributors. Dashboards gain public read-only links, a TV mode, a layout editor with undo, live panel preview and four new panel types; the metrics explorer v2 can create alerts from any chart, compare periods, forecast, write formulas and use Prometheus 3.x functions. Product analytics and continuous profiling are included out of the box alongside dozens of alerting improvements.

  • Grafana MCP v2.4.0 adds notebook tools and opt-in AWS X-Ray trace tooling grafana/mcp-grafana - released 24 Nov 2026 10:01 UTC

    The release adds tools for the Grafana 13.3 notebooks preview: list, search, get by UID, render to PDF, create, update and delete. The update tool keeps the notebook metadata and checks the resourceVersion it was read at, so a concurrent edit fails instead of being overwritten. An opt-in xray category adds search_xray_traces and get_xray_trace, the latter returning a trace as a tree of segments with timings and HTTP status codes.

  • Grafana v13.3.2 fixes two CVEs and preserves folder identities during provisioning grafana/grafana - released 24 Nov 2026 17:58 UTC

    The patch release fixes CVE-2026-107561 and CVE-2026-88960. Its provisioning change keeps existing folder identities when children are created instead of regenerating them, so dashboards and folders produced by the same provisioning job keep stable identifiers across runs.

  • Grafana Beyla v3.44.0 adds GPU metrics collection to the eBPF auto-instrumentation grafana/beyla - released 25 Nov 2026 10:27 UTC

    Beyla v3.44.0 adds GPU metrics collection and export, and makes server.address and server.port opt-in on HTTP request duration and body size so those labels are no longer emitted by default. It also carries upstream changes from opentelemetry-ebpf-instrumentation, including Go channel links moved to runtime configuration, preserved custom query-parameter redaction in Config v2 and runtime.goexit1-based Go exception cleanup.

  • Prometheus Alertmanager v0.35.1 raises the HTTP server idle timeout so alert deliveries are not cut off prometheus/alertmanager - released 24 Nov 2026 22:47 UTC

    The fix raises the Alertmanager HTTP server idle timeout from 90 seconds to 6 minutes, outlasting the 5-minute client idle timeout used by Prometheus, so alert POSTs are no longer failed by connections closed on the server side.
